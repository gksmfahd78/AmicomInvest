# 아미콤 · 스터디 투자실

React + TypeScript + Node.js로 만든 스터디용 국내 주식 모의투자 웹앱입니다.
관리자가 가상 투자금을 지급하고 회원이 종목 차트·호가를 확인하며 매매합니다.

## 실행

Node.js 22.13 이상이 필요합니다. Node의 내장 SQLite를 사용합니다.

```powershell
cd D:\study
npm install
Copy-Item .env.example .env
npm run dev
```

개발 화면: http://127.0.0.1:5173
서버: http://127.0.0.1:3001

배포 빌드를 로컬에서 확인하려면:

```powershell
npm run build
npm start
```

이 경우 http://127.0.0.1:3001 에서 화면까지 제공합니다.

## 첫 로그인

- 관리자 아이디: `admin`
- 초기 비밀번호: `Study!2026`
- 회원 초대 코드: `STUDY2026`

위 값은 로컬 개발 기본값입니다. 스터디에 공개하기 전에 .env의 ADMIN_PASSWORD와 STUDY_INVITE_CODE를 정하고 **최초 실행**하세요.
관리자 계정은 DB에 관리자가 없을 때만 생성되므로, 기존 계정 비밀번호는 .env 변경으로 바뀌지 않습니다.
기존 데이터가 있는 상태의 관리자 비밀번호 변경은 아래 명령으로 가능합니다. 기존 세션도 해제합니다.

```powershell
$env:NEW_ADMIN_PASSWORD='새로운-긴-비밀번호'
npx tsx server/reset-admin.ts
Remove-Item Env:NEW_ADMIN_PASSWORD
```

가입 시 현금은 0원입니다. 관리자 화면에서 대상을 선택하고 가상 투자금을 지급하세요.
관리자 본인에게도 지급할 수 있습니다.

## 시세 연결

기본값 `MARKET_PROVIDER=demo`는 **합성 샘플 데이터**입니다. 실제 종목명만 사용하며 가격·차트·호가는 실제 값이 아닙니다.
샘플 모드는 시간과 무관하게 거래할 수 있습니다. 이 데이터로 시작한 계좌는 실제 시세 계좌와 섞지 마세요.

한국투자증권 API를 사용할 때는 서버의 .env에 다음 값을 설정하고 재시작하세요:

```dotenv
MARKET_PROVIDER=kis
DATABASE_PATH=./data/study-kis.sqlite
KIS_APP_KEY=발급받은_앱키
KIS_APP_SECRET=발급받은_앱시크릿
BROKER_COMMISSION_BPS=1.5
SELL_TAX_BPS=15
```

키는 브라우저에 전달하지 않습니다. 실제 주문 API를 호출하는 코드는 없습니다.
거래비용은 모의 계산값입니다. `1bp=0.01%`이며 증권사·시장 정책에 맞춰 환경 변수로 조정할 수 있습니다. 기존 주문에는 소급 적용하지 않고 새 주문부터 적용합니다.
현재가·캔들·호가 REST API와 KIS WebSocket 시세를 사용합니다. 실시간 연결 실패 시 15초 조회 방식으로 보완합니다.
API 응답 캐시와 요청 직렬화가 적용되어 있습니다. 연결 실패 시 샘플 가격으로 대체하지 않습니다.
데이터 이용 및 회원 대상 표시 가능 범위는 제공처의 계약을 확인해야 합니다.

## 프로젝트 구조

- `src/App.tsx`: 거래, 계좌, 관리자, 랭킹, 로그인 화면
- `src/Chart.tsx`: SVG 캔들 및 거래량 차트
- `server/index.ts`: HTTP API, 인증 및 미체결 처리
- `server/db.ts`: SQLite 스키마, 지급 및 체결 트랜잭션
- `server/market.ts`: 샘플/KIS 시세 어댑터 및 초기 종목 목록
- `data/`: 실행 시 생성되는 데이터베이스 (버전 관리 제외)

현재 단일 스터디, 단일 서버 기준 SQLite를 사용합니다.
여러 스터디 운영이나 여러 서버 배포 시 PostgreSQL과 작업 큐로 확장할 수 있습니다.
외부 배포 전 HTTPS, 운영 비밀번호, 초대 코드, 백업과 운영 환경을 설정해야 합니다.
기본 바인딩은 127.0.0.1이므로 로컬에서만 접속됩니다.

## 코스피 · 코스닥 전체 주식

한국투자증권 공식 종목 마스터를 내려받아 전체 주식 목록을 제공합니다.
주식·외국주식·주식예탁증서·리츠·투자회사와 ETF를 포함하며 ETN·ELW·신주인수권은 제외합니다.
시장 필터, 종목명·코드 검색, 관심 종목, 10종목 단위 페이지를 지원합니다.
시세 API는 페이지에 표시되는 최대 10종목만 요청합니다. 거래 화면의 목록은 전체 시장 동시 시세 순위가 아닙니다. 시장 분석 페이지는 별도의 제공처 순위 API를 사용합니다.

목록 캐시는 data/stock-master.json에 저장되며 서버 시작 시 24시간 이상 지난 경우 및 실행 중 매일 갱신합니다.
갱신 실패 시 기존 캐시를 유지합니다. 수동 갱신: npm run sync:stocks (이후 서버 재시작).
최초 실행 환경에서 다운로드가 실패하고 캐시도 없으면 기존 기본 종목으로 실행합니다.

공식 형식: https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/kis_kospi_code_mst.py
및 https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/kis_kosdaq_code_mst.py

## 고도화 기능

1. 차트: PC는 최근 100봉, 모바일은 50봉을 기본으로 표시하고 화면 밖의 이전 봉도 지표 계산에 사용합니다. ‘과거 더 보기’로 100봉씩 추가하며 보고 있던 구간은 유지합니다. 상장 초기처럼 원본 데이터가 부족한 구간에는 이동평균을 임의로 만들지 않습니다. 일·주·월 단위를 구분합니다. 이동평균선 5·20·60, 거래량, 볼린저 밴드(20,2), EMA(20), RSI(14), MACD(12,26,9), 스토캐스틱(14,3,3), CCI(20), MFI(14), OBV, ATR(14)를 선택해 표시합니다. 보조지표 설정에서 종류별 설명과 조합을 고를 수 있고 계정별로 브라우저에 선택을 저장합니다. 볼린저밴드는 음영·상중하단 가격·%B·밴드 폭으로 표시하며 중심선과 같은 SMA20은 중복해서 그리지 않습니다. 지표 패널은 각각 높이를 확보하고 현재 값·범례·참고선을 표시합니다. 모바일 선택 도구에서는 차트 위 세로 스크롤이 가능합니다.
2. 실시간: 서버에서 KIS H0STASP0(10호가)·H0STCNT0(체결 시세)를 수신해 인증된 SSE로 현재 선택 종목에 전달합니다. 키는 서버에만 있습니다. 재연결·수신 상태 표시 및 REST 대체 조회를 지원합니다. 서버 연결 하나에서 최대 20종목(40개 구독)을 공유하며 대기 주문 종목을 우선합니다. 초과 종목은 REST 조회로 처리합니다.
3. 체결: 매수는 매도호가, 매도는 매수호가를 가격 우선·접수 순으로 소진합니다. 지정가는 한도 내 부분 체결, 시장가는 제공 호가 내 부분 체결 후 잔량 취소입니다. 동일 가격의 모의 사용 수량은 다른 호가 변화·표시 범위 이탈·서버 재시작만으로 복원되지 않습니다. 당일 누적 거래량이 증가하면 그 증가량을 한도로 현재 표시된 가격의 모의 사용 수량을 줄여 잔량을 복원합니다. 같은 거래량을 반복 수신하거나 감소한 거래량은 복원에 사용하지 않습니다. 다음 한국 날짜의 새 호가에서 초기화합니다.
4. 규칙: KIS 휴장일·거래 정지·VI 이벤트·호가의 장 운영 상태와 국내 주식 호가 단위·상하한가를 검사합니다. KIS 모드는 표준 일반 거래 구간 09:00~15:20에만 신규 주문·정정·체결하며, 시가·종가 단일가와 시간외에는 보류합니다. 새 미체결 주문은 당일 15:30 만료합니다. 샘플 모드는 시간 제한 없이 24시간 유효합니다. 업그레이드 전 주문은 기존 유효기간을 유지합니다.
5. 주문: 체결 진행률·개별 체결 내역·실시간 알림을 표시합니다. 정정은 남은 수량 이하로만 가능하며 기존 주문 잔여분 취소와 새 주문 접수를 한 트랜잭션으로 처리합니다. 실패 시 원래 주문을 보존하고 추가 체결이 생겼으면 재확인을 요구합니다. 새 주문은 새 접수 순서를 가지며 기존 체결은 유지합니다.
6. 그림: 계정·종목·봉 종류별 SQLite 저장과 브라우저 백업을 지원합니다. 서버 저장본이 없으면 기존 로컬 그림을 옮깁니다. 동시 수정 충돌은 덮어쓰지 않고 오류와 재시도·서버 다시 불러오기를 표시합니다. 저장 중에는 차트 닫기·봉 전환을 보류합니다.
7. 거래비용·기업행사: 환경 변수로 설정한 매매 수수료와 매도세를 예약금·취득원가·실현손익에 반영합니다. 현금배당과 주식분할·병합을 관리자가 중복 없이 적용하며 분할 시 미체결 주문을 취소합니다.
8. 분석·운영: 매도 승률·평균 실현손익·손익비·최대 낙폭·매매 이유 작성률과 KIS REST/실시간 연결 진단을 제공합니다.
9. 대회: 관리자가 종료일을 정해 대회를 시작하면 현재 멤버 전원의 평가자산과 KOSPI 기준값을 저장합니다. 대회 중 추가 지급금은 수익에서 제외하며, 종료일 15:30(KST)에 참가자 평가자산과 KOSPI를 고정합니다. 진행 중 대회는 사유를 남겨 취소할 수 있으며 계좌·거래 기록은 유지됩니다. 종료·취소된 대회도 선택해 이력을 확인할 수 있습니다.

실제 거래소에 주문을 보내지 않는 모의 엔진입니다. 거래소의 내 앞 대기 주문이나 실제 잔량 감소 원인은 알 수 없어 잔량 추정은 보수적이며 실제 체결과 다를 수 있습니다. 동시호가·VI 단일가 체결을 재현하지 않으므로 해당 구간에는 일반 체결을 보류합니다. 특별 개장시간·결제일 처리는 모델링하지 않습니다. 특수 거래일에도 표준 일반 거래 시간과 제공처 상태를 함께 검사하므로 실제 거래 가능 구간보다 보수적으로 제한될 수 있습니다.

추가 파일: `server/realtime.ts`, `server/trading.ts`, `server/drawings.ts`, `src/tradingRules.ts`, `src/useDrawingSync.ts`.

검증: `npm test` (체결/잔량/정정/만료/그림 충돌/실시간 파싱), `npm run test:ui` (주문·권한·과거 차트·다른 브라우저 그림 저장).

## 종목 테마 분류

한국투자증권의 [공개 테마 마스터](https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/theme_code.py)를 사용합니다. 테마명은 제공처의 명칭을 그대로 표시하고, 한 종목에 여러 테마를 연결합니다. 분류가 없는 종목은 `테마 미분류`로 표시합니다.

종목 탐색의 `테마` 선택과 검색창을 함께 사용할 수 있습니다. 예를 들어 `HBM`, `반도체 삼성`으로 검색하고 코스피·코스닥 및 관심 종목 조건과 조합할 수 있습니다. 선택 종목의 `관련 테마`를 펼쳐 테마를 누르면 같은 테마 종목을 탐색합니다.

서버가 `data/stock-themes.json`에 분류를 저장하고 하루마다 갱신합니다. 갱신에 실패하면 마지막 분류를 유지하며, 초기 조회가 실패해도 일반 종목 검색은 사용할 수 있습니다. 테마 출처와 마지막 수집 날짜는 종목 탐색 하단에 표시합니다. API는 로그인 후 `GET /api/stock-themes`로 조회합니다.

## 시장 분석

트레이딩 바로 아래의 **시장 분석**에서 코스피·코스닥 지수와 상승·하락 종목 수, 상·하한가 포착, 상승률·하락률·거래량·거래대금·전일 거래량 대비 증가 순위를 조회합니다. 시장·날짜·종목·테마로 좁히고 종목을 누르면 거래 화면으로 이동합니다. 모바일에서는 종목별 카드로 표시합니다.

한국투자증권 순위 API의 상위 조회 결과 중 서비스에서 지원하는 주식 목록을 표시합니다. 전체 시장의 모든 종목을 전수 조사한 결과가 아니며, 테마 집계도 조회된 상승률 순위 종목 기준입니다. 상·하한가 판정은 제공된 상·하한가격과 현재가 일치로 확인합니다. 포착된 종목은 이후 이탈해도 최초·최근 확인 시간과 함께 남기며 가격과 거래량은 최근 포착 당시 값입니다.

서버 시작 시 및 평일 09:00~15:50(KST)에 5분마다 시장별 기록을 수집합니다. 최신 화면은 1분마다 조회하며 서버 캐시는 1분입니다. 기록은 `data/market-analysis/{kis|demo}/YYYY-MM-DD-{ALL|KOSPI|KOSDAQ}.json`에 저장되어 재시작 후에도 유지됩니다. 과거 기록은 수집 시작일 이후부터 쌓이며, 수집 사이에 잠시 도달한 종목은 누락될 수 있습니다. 조회 실패 시 마지막 저장 시각과 지연 안내를 표시하며 임의의 시세로 대체하지 않습니다. 로그인 후 `GET /api/market-analysis?market=ALL&date=YYYY-MM-DD`로 조회하며 날짜 생략 시 최신 거래일을 반환합니다.

공식 자료: [상·하한가](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/capture_uplowprice/capture_uplowprice.py), [등락률 순위](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/fluctuation/fluctuation.py), [거래량 순위](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/volume_rank/volume_rank.py).

## Docker 배포

운영 설정은 `.env`, 영속 데이터는 `data/`에 보관하며 이미지에는 포함하지 않습니다. SQLite backup API로 운영 DB를 백업한 뒤 `docker compose build app` 및 `docker compose up -d --no-deps app`으로 배포합니다. 컨테이너는 `127.0.0.1:3116`에서 응답하며 기존 HTTPS 프록시가 연결됩니다. `/api/meta`와 컨테이너 health 상태로 기동을 확인합니다.

### 시장 분석 고도화

- 첫 진입은 `종목` 탭이며 지수의 간단한 요약 다음에 순위를 배치합니다. `요약·종목·테마·뉴스` 탭은 화면 상단에 고정하고 URL의 `analysisTab`으로 새로고침·뒤로가기에서 복원합니다. 요약 탭에는 시장 전체 상승·하락 분포와 장중 기록, 종목 탭에는 순위 및 조건 검색, 테마 탭에는 5개씩 펼쳐 보는 비교 목록을 제공합니다.
- 모바일 순위는 선택한 지표의 등락률·거래량·거래대금·전일 거래량 대비 배수를 크게 표시합니다. 상·하한가 목록의 `최근 수집 때 도달`, `장중 포착`, `조회 지연` 상태는 펼치지 않아도 보이며 상세에는 최초·마지막 도달 시각을 표시합니다. ‘도달’은 현재 실시간 상태를 보장하지 않습니다.
- 시장 요약은 지수 등락과 전체 상승 종목 비율(보합 포함)을 함께 표시합니다. 상승률 순위 표본으로 시장 전체 분위기를 추정하지 않습니다.
- 테마 비교는 정상 조회된 순위 목록의 종목을 중복 제거해 등락률 중앙값, 상승 종목 수, 거래대금 합계와 표본 수를 계산합니다. 테마 전체 수익률이나 순매수 자금이 아닙니다. 거래대금 미제공 종목 수를 구분하며 현재 테마 분류를 사용합니다.
- 조건 검색은 등락률, 거래대금(억 원), 전일 하루 거래량 대비 배수, 테마를 조합합니다. 조건에 필요한 값이 없는 종목은 제외합니다. 전일 동시간대 거래량 증가율과는 다릅니다.
- 일별 JSON의 `history`에 5분 구간별 최신 관측을 최대 300개 보관합니다. 지수 전일 대비 등락률 추이와 시점 선택을 제공하고 누락된 수집 구간을 채우지 않습니다. 기존 JSON 파일은 그대로 읽으며 저장된 마지막 관측부터 기록을 이어갑니다.
- 자동 새로고침 때 기존 화면과 펼침·검색 상태를 유지합니다. 시장이나 날짜를 바꾸면 이전 결과를 지워 잘못된 조건의 데이터를 표시하지 않습니다.

### 종목별 관련 뉴스

트레이딩에서 선택한 종목의 관련 뉴스를 PC에서는 종목 상세 아래, 모바일에서는 `뉴스` 탭에 표시합니다. 매일경제·한국경제·연합뉴스·비즈니스포스트·파이낸셜뉴스·전자신문·뉴시스의 공식 RSS 목록에서 제목에 종목명 또는 코드가 언급된 기사를 찾습니다. NAVER는 네이버 표기도 인식하며 짧은 일반어 종목명은 증권 관련 표현을 함께 검사합니다. 본문을 검색하는 기능이나 모든 종목의 전체 과거 기사 검색은 아닙니다. 매칭 결과가 없으면 이를 명확히 안내합니다.

기사 제목·발행 시각·출처·원문 링크만 제공하며, 본문·사진은 저장하거나 재게시하지 않습니다. 제목은 종목 연관성을 찾는 기준이며 주가 변동 원인을 확정하지 않습니다. 언론사 필터로 출처별 뉴스를 선택할 수 있고, 언론사별 최대 20건을 최신순으로 표시합니다. 동일 URL은 중복 제거하고 다른 언론사의 같은 제목은 출처를 구분해 유지합니다. 서버에서 각 피드를 5분간 공유 캐시합니다. 공급 장애가 난 피드만 1분 후 재시도하며 마지막 정상 결과는 최대 6시간 유지하고 지연 상태와 원래 수집 시각을 표시합니다. 공개 RSS에 포함된 최근 7일 이내 기사만 처리합니다. 로그인 후 `GET /api/stock-news?symbol=005930`로 조회합니다. 별도 API 키나 유료 구독 로그인 정보는 사용하지 않습니다.

뉴스 피드 출처: [매일경제](https://www.mk.co.kr/rss/), [한국경제](https://www.hankyung.com/feed), [연합뉴스 경제](https://www.yna.co.kr/rss/economy.xml), [비즈니스포스트](https://www.businesspost.co.kr/2022/sub/rss.jsp?left_menu=14). 총 16개 피드의 최근 7일 목록을 사용합니다. 출처는 서버 설정과 기사 도메인을 함께 검증해 지정하고, 기사 조회에 필요한 비즈니스포스트의 `command=article_view&num=...`는 보존하며 추적용 쿼리는 제거합니다.

추가 뉴스 출처: [파이낸셜뉴스](https://www.fnnews.com/rss)의 증권·산업, [전자신문](https://www.etnews.com/rss/?Id=1)의 전자·반도체/SW·AI/경제·금융, [뉴시스](https://nwww.newsis.com/RSS/)의 산업·금융입니다. 모바일에서는 언론사 선택창으로 전체 7개 출처를 선택할 수 있습니다.

뉴스 분석은 기본 `이슈별` 보기에서 36시간 이내의 유사 제목을 묶으며 `최신순`으로 개별 기사를 볼 수 있습니다. 묶음의 모든 기사끼리 유사성을 확인하고, 수치가 다르거나 취소·부인 및 상승·하락 방향이 다른 제목은 분리합니다. 자동 묶음은 같은 사건임을 보증하지 않으며 펼치면 언론사별 제목·시각·원문 링크를 모두 확인할 수 있습니다. 실적, 수주·계약, 배당·자사주, 증자·자금조달, 인수·합병, 소송·규제, 제품·기술, 증권사 분석, 주가·시장, 기타 유형을 제목의 표현으로 분류하고 언론사·유형·날짜 필터를 함께 적용합니다. 호재·악재나 인과관계를 추정하는 기능은 아닙니다.

`발행일 차트 보기`는 일봉으로 전환해 KST 발행일과 정확히 같은 날짜의 봉을 강조합니다. 시가·종가/최근가·전 거래일 대비 등락과 발행 시각(정규장 09:00~15:30 시간대 기준)을 함께 보여 줍니다. 분봉 데이터가 없으므로 기사 발표 순간의 가격이나 발표 이후 수익률을 표시하지 않습니다. 해당 날짜의 봉이 없으면 다른 날로 대체하지 않으며, 장 마감 후 기사는 당일 종가가 발행 전 가격임을 표시합니다. 차트 위 점과 아래 날짜 버튼은 수집한 뉴스가 있는 거래일을 나타내며 날짜를 누르면 그날 뉴스로 이동합니다. 범위는 현재 RSS 목록과 화면에 표시된 일봉이며 장기 뉴스 이력을 저장하지 않습니다.

시장분석의 `시장 이슈 브리핑`에서는 정상 수집된 순위 표본의 거래대금 상위·상승률 상위·현재 상한가 포착·현재 하한가 포착 종목 중 최대 8개를 비교합니다. 지원 종목만 선택하고 중복 표본과 오류 지표는 제외합니다. 거래대금 결측값은 거래대금 순위에서 제외하며 현재 상·하한가는 `active=true` 기록만 사용하며 하한가 목록은 하락폭이 큰 순서로 정렬합니다. 각 종목의 등락률·표본 거래대금·테마·수집 시각과 관련 뉴스 이슈를 함께 표시하고, 기사에서 트레이딩의 발행일 일봉으로 이동할 수 있습니다.

브리핑은 뉴스 탭에 진입할 때 기존 인증 뉴스 API를 최대 3개 동시 요청으로 조회하고, 탭이 열려 있는 동안 5분마다 갱신합니다. 날짜·시장·대상 종목이 바뀌면 이전 요청을 취소하고 결과를 분리하며 일부 종목의 공급 장애는 다른 종목을 가리지 않습니다. 같은 대상의 갱신 실패 시 이전 결과에 지연 안내를 붙입니다. 선택한 분석 날짜와 같은 KST 발행일 및 뉴스 유형으로 필터링합니다. 원문 URL을 중복 제거해 최근 이슈 3개부터 보여 주고 더 보기로 이어집니다. 기사 없는 종목은 큰 카드 대신 간단한 조회 현황에 표시합니다. 원문 건수는 여러 종목에 연결된 같은 URL을 한 번만 집계합니다. 뉴스는 현재 RSS 목록에서 조회하므로 과거 분석 기록의 완전한 뉴스 아카이브가 아닙니다.

### 8주 투자 교육과 발표 자료

`투자 교육`은 로그인한 모든 멤버가 이용하는 별도 페이지입니다. `/#education/week/1`부터 `/#education/week/8`까지 주차 링크로 직접 열고 공유할 수 있습니다. 주식 입문자 기준 주 90분(설명·확인 문제 40분, 사례 풀이 20분, 실습 20분, 토론 10분)의 원본 교육 자료입니다. ① 투자 기초 ② 호가·주문 ③ 기업·재무제표 ④ 가격·가치 비교 ⑤ 시장·테마·뉴스 ⑥ 분산·ETF ⑦ 계획·복기 ⑧ 최종 발표 순서이며, 총 96장 슬라이드에 주차별 목표·가상 계산 예시·진행자 메모·실습·토론·과제·확인 문제가 포함됩니다. 강의 본문은 교육용 가상 기업 한빛식품의 사례로 구성합니다. 주식 지분·계좌 손익·호가별 체결부터 DART에서 자료를 찾는 절차, 원가율·현금흐름 분석, EPS·PER 비교, 계약 뉴스의 조건, ETF 중복 노출, 복기와 완성 발표 원고까지 연결합니다. 각 소단원은 입력 자료, 구체적인 계산, 해석과 잘못된 해석, 작성할 분석 문장을 포함합니다. 가상 공시·기사 문장은 실제 원문 인용과 명확히 구분합니다. 발표 자료 앞부분과 진행자 메모에도 같은 계산과 원고를 반영합니다. 강의 본문 24개와 핵심 정리, 계산표와 단계별 풀이 8개, 자주 묻는 질문 24개, 힌트·해설이 있는 추가 연습문제 24개를 제공합니다. 본문은 첫 소단원을 펼쳐 보여 주며, 단계별 풀이는 하나씩 확인하거나 다시 시작할 수 있고 주차 변경 시 초기화됩니다. 사전 읽기와 수업 후 복습 자료로도 활용할 수 있습니다. 상세 해설 16개, 주차별 사례 문제와 모범 답안, 활동지 질문 40개도 제공합니다. KRX, DART, SEC, Investor.gov, FINRA의 공식 참고 링크를 주차별로 제공합니다.

`발표 시작`이나 미리 보기의 `이 슬라이드부터 발표`로 발표 화면을 열 수 있습니다. 방향키와 PageUp/PageDown으로 이동하고 Home/End로 처음·마지막 슬라이드를 선택하며 Escape로 종료합니다. 브라우저가 지원하면 전체 화면으로 전환할 수 있습니다. 진행자 메모는 선택 시 현재 발표 화면에도 보이며 별도 비공개 화면이 아닙니다. `슬라이드 PDF`는 해당 주차의 발표 자료 12장을 가로 A4로, `교재·활동지 PDF`는 해설·사례·풀이·활동지와 강의 본문·단계별 예제·질문·연습문제 및 해설 12장을 세로 A4로 인쇄합니다. 각 버튼의 인쇄 창에서 PDF 저장을 선택할 수 있습니다. 확인 문제 응답은 현재 화면에서만 사용하며 성적이나 완료 이력으로 저장하지 않습니다. 실습 버튼은 해당 모의투자 화면으로 이동할 뿐 주문을 자동 제출하지 않습니다.

모바일 하단 메뉴는 트레이딩·시장 분석·투자 교육·내 계좌·더보기의 5개로 유지합니다. 랭킹과 로그아웃, 관리자 전용 메뉴는 더보기 창에 표시합니다. 교육 내용은 `src/investmentCourse.ts`, `src/courseDepth.ts`, `src/courseLessons.ts`, 발표·학습 UI는 `src/InvestmentEducation.tsx`와 `src/CourseSeminar.tsx`에서 관리합니다.


## 계좌 성과·투자 일지·위험 분석

`내 투자 계좌`에서 계좌 수익률 기록, 투자 일지, 포트폴리오 위험 분석을 이용합니다.

- **성과 수집:** 화면 조회와 독립된 서버 작업이 시작 시 한 번, 평일 KST 09:00~15:35 구간에 5분 간격으로 모든 계좌를 평가합니다. 데모 모드는 상시 수집합니다. 공유 종목 시세는 한 번씩, 최대 3개 동시 요청으로 조회합니다. 보유 종목에 60초 이내의 유효한 시세가 없으면 해당 계좌의 평가를 건너뜁니다. 동일 5분 구간의 자동 기록은 중복 저장하거나 덮어쓰지 않습니다.
- **지급금 보정:** 투자금 지급 시 최신 보유 시세를 확보한 뒤, 동일 트랜잭션에서 지급 전 평가 → 지급 → 지급 후 평가를 기록합니다. 두 평가 사이에는 투자 수익을 발생시키지 않고, 나머지 구간의 평가액 비율을 곱해 수익률과 관측 최대 낙폭을 계산합니다. 지급 시 평가가 불가능해도 지급 자체는 유지하며, 이후 해당 구간을 포함하는 수익률과 낙폭은 추정하지 않고 누락 안내를 표시합니다. 금액 손익은 `기말 평가액 - 기초 평가액 - 추가 지급액`입니다. 배당과 거래비용은 계좌 평가액에 반영됩니다.
- **기록 범위:** 신규 `performance_points` 테이블을 사용합니다. 과거 화면 조회로 쌓은 `equity_snapshots`를 새 수익률 기록으로 소급 변환하지 않습니다. 최대 낙폭은 수집한 관측값 기준이며 틱 단위 낙폭이 아닙니다. 지수는 같은 관측 시작·종료 시점의 KOSPI/KOSDAQ 가격지수와 비교하고, 기준값이 없으면 표시하지 않습니다. 데모의 비교 지수는 고정된 가상 값입니다. 최근 24시간/7일/30일 또는 전체 기록을 조회하고, KST 일별·월별·월요일 시작 주별 손익을 볼 수 있습니다. 표시한 실제 시작 시점 이전 성과는 포함하지 않습니다.
- **투자 일지:** 주문 폼의 매매 이유와 선택 항목인 예상 보유 기간·판단을 바꿀 조건·근거 자료를 주문 당시 계획으로 저장합니다. 서버가 수신한 최우선 매수·매도 호가와 시각도 보존합니다. 주문·계획 저장은 하나의 트랜잭션이며 재시도는 중복 생성하지 않습니다. 정정 주문은 최초 계획을 이어받고 새 호가를 기록합니다. 원래 계획은 사후 변경할 수 없으며, 판단 평가·계획 준수 여부·배운 점은 복기로 저장하고 수정할 수 있습니다. 다른 화면의 수정과 충돌하면 덮어쓰지 않습니다.
- **과거 일지:** 기존 주문에도 복기를 작성할 수 있지만 당시 계획의 추가 항목과 호가를 소급 생성하지 않습니다. 회원 본인의 주문만 접근할 수 있습니다. 20건씩 페이지를 조회하며 기존 계좌 화면의 최근 200건 제한과 무관하게 전체 주문을 종목·복기 상태로 필터링합니다.
- **위험 분석:** 현금을 포함한 계좌 전체 평가액 대비 종목별·상위 3종목·현금 비중, 종목별 평가손익, 제공된 업종과 테마 노출을 표시합니다. 현재 종목 마스터의 ‘주식·리츠’ 등 상품 분류는 업종으로 오인하지 않고 ‘업종 미분류’로 표시합니다. 여러 테마에 속한 종목은 각 테마에 포함되므로 테마 비중끼리 합산하지 않습니다. 일부 시세가 없으면 부분 계좌 비중을 전체 비중으로 표시하지 않습니다.
- **가상 계산:** 주식 전체 또는 특정 보유 종목의 5/10/20/30% 가격 하락 시 계좌 평가액 변화를 계산합니다. 가격 예측·상관관계·매도 비용은 반영하지 않습니다. 주문 화면에는 주문 전량 체결과 예상 가격·비용을 가정한 해당 종목 비중을 표시합니다. 시장가의 전체 수량을 현재 호가로 예상할 수 없거나 현금·보유 수량이 부족하면 안내하지 않습니다.

관련 구현: `server/performance.ts`, `server/journal.ts`, `src/AccountLearning.tsx`, `src/portfolioRisk.ts`. 서버 계산·권한·회귀 검증은 `npm test`, 브라우저 흐름은 `tests/account-learning.spec.ts`에 있습니다.


## 모의 체결 고도화 (4단계)

- **공통 상태 검사:** `src/executionRules.ts`와 `server/trading.ts`를 신규 주문·정정·자동 체결에 적용합니다. KIS 휴장일, 거래 정지 여부, 당일 해당 종목의 VI 발동·해제 이력을 확인합니다. VI 기준 가격이나 적용 대상 플래그만으로 발동을 판단하지 않으며, 발동 후 일정 시간이 지났다는 이유로 해제하지 않습니다. 이벤트 형식이 잘못됐거나 조회가 실패하면 체결을 보류합니다. 종목 상태는 최대 3초 캐시를 공유하며 실제 제공처 수신 지연은 있을 수 있습니다.
- **호가 구간 검사:** KST 시간 경계에 더해 REST `new_mkop_cls_code`와 WebSocket `HOUR_CLS_CODE`를 검사합니다. 정상 일반 거래로 확인한 값 이외의 상태, 교차 호가, 오래된 호가는 체결에 사용하지 않습니다. 미체결 주문의 취소는 보류 구간에도 가능합니다. API 응답을 기다리는 동안 종가 단일가가 시작된 경우도 다시 검사합니다.
- **거래량 기반 복원:** WebSocket 호가의 `ACML_VOL` 또는 REST 호가에 연결한 최신 현재가의 누적 거래량을 사용합니다. `liquidity_recovery`에 종목별 당일 기준점을 저장하고, 증가 수량만큼 표시된 가격의 모의 사용 잔량을 줄입니다. 양쪽 매수·매도 합계 복원량은 그 증가량을 넘지 않습니다. 사용하지 않은 증가분을 미래 복원 예산으로 적립하지 않습니다. 누락·역행·전일 값은 복원하지 않으며, 잔량과 기준점 변경은 주문 실패 시 함께 롤백합니다. 실제 취소·신규 주문이나 거래소 대기열을 식별한 알고리즘은 아니므로 추정 모형임을 주문 화면에 설명합니다.
- **체결 근거:** 개별 체결에 최우선 상대 호가, 수신 시각, 해당 가격의 배분 전 모의 잔량과 배분 설명을 저장합니다. 주문 내역을 펼치고 ‘체결 상세’를 열면 확인할 수 있습니다. 지정가 조건 대기, 모의 잔량 대기, VI·거래 상태 보류, 시장가 잔량 취소를 구분해 표시합니다. 기존 체결의 당시 근거를 소급 생성하지 않습니다.

근거로 확인한 공식 자료:

- [KIS 호가 상태 필드](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_asking_price_exp_ccn/chk_inquire_asking_price_exp_ccn.py)

## ETF 모의투자

종목 탐색에서 `전체 상품 / 주식 / ETF`를 고를 수 있습니다. 시장·관심 종목·테마 필터와 함께 적용되며, ETF는 종목 및 보유 내역에 별도로 표시됩니다. 한국투자증권 종목 마스터의 `EF` 그룹으로 판별하며 클라이언트의 상품 유형·세율 입력을 신뢰하지 않습니다. 캐시 형식 v2 이전 목록은 시작 시 즉시 갱신을 시도하고, 실패하면 기존 목록을 유지합니다.

ETF 지정가는 2,000원 미만 1원, 이상 5원 단위입니다. 매매 수수료는 기존 설정을 적용하고 매도 증권거래세는 0원으로 기록합니다. 주문에 상품 유형을 보존하여 정정·재시작 이후에도 같은 규칙을 적용합니다. ETF의 매매차익·분배금 소득세와 분배금 자동 지급은 미반영입니다. 펀드 내부 보수는 NAV에 이미 반영되므로 별도로 차감하지 않습니다.

ETF 차트 화면에서 NAV, 조회 당시 거래 가격과 NAV 대비 가격 차이, 기준 지수, 추적 수익률 배수를 확인할 수 있습니다. `/api/etf/:symbol`은 인증 후 ETF만 조회하며 KIS `FHPST02400000` 응답을 30초 캐시합니다. 가격 차이는 한 응답의 가격·NAV로 계산하지만 각 원천 평가 시점이 같음을 보장하지 않으므로 조회 시점과 해석 범위를 표시합니다. 누락된 NAV는 0으로 채우지 않습니다. 데모 값은 가상 수치로 명시합니다. ETF 구성 자산의 중복 노출은 아직 분해하지 않습니다.

검증 근거: [호가 단위 축소 연구와 시행일](https://www.kcmi.re.kr/publications/pub_detail_view?cno=6382&syear=2024&zcd=002001016&zno=1799), [KRX ETF 세금 안내](https://regulation.krx.co.kr/contents/RGL/03/03060105/RGL03060105.jsp), [KIS ETF 현재가 공식 예제](https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/etfetn/inquire_price). 거래소의 요약 매매절차 페이지에 남아 있는 고정 5원 설명과 달리, 2023-12-11 시행된 저가 ETP 1원 단위를 반영합니다.

### 보조지표 계산 기준

`src/chartIndicators.ts`는 화면에 보이는 구간을 자르기 전 전체 로딩된 봉으로 계산합니다. 기간은 선택한 봉 단위이며 EMA·MACD는 초기 SMA를 시드로, RSI·ATR은 Wilder 평활화를 사용합니다. 스토캐스틱은 Fast %K의 3봉 SMA와 그 결과의 3봉 SMA입니다. ATR 첫 봉의 TR은 고가−저가로 시작합니다. OBV는 불러온 첫 봉을 0으로 삼으므로 과거 봉을 추가하면 기준값이 달라질 수 있습니다. CCI는 전형가격의 평균 절대편차를, MFI는 전형가격 상승·하락에 따른 거래량 가중값을 사용합니다.

필요한 데이터가 없으면 `null`(계산 대기)을 유지합니다. 변동·방향성 자금흐름이 모두 0인 구간은 RSI·스토캐스틱·MFI 50, CCI 0으로 처리합니다. 볼린저 폭이 0이면 %B는 계산 불가이며, 밴드 밖의 %B는 0~100으로 제한하지 않습니다.

계산 참고: [Fidelity 지표 안내](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide), [TradingView 스토캐스틱](https://www.tradingview.com/support/solutions/43000502332-stochastic-stoch/). 검증은 `server/chart-indicators.test.ts`와 `tests/chart-indicators.spec.ts`에 있습니다.

### 확대·축소와 봉 자동 전환

차트 분석실의 확대·축소 버튼은 기본적으로 월봉 ↔ 주봉 ↔ 일봉을 이어서 탐색합니다. 확대 후 목표 봉 수가 20개 미만이면 더 세밀한 봉으로 전환하고, 축소 후 160개를 넘거나 현재 로딩된 구간 끝에 도달하면 더 큰 봉으로 전환합니다. 일봉 확대는 최소 10개, 월봉 축소는 로딩된 전체 범위까지입니다. `봉 자동 전환`을 끄면 봉 종류를 고정하며 선택은 계정별 브라우저에 저장됩니다.

PC에서는 차트 위에서 `Ctrl + 마우스 휠`(Mac은 Command도 지원), 모바일에서는 두 손가락을 벌리거나 모아서 확대·축소합니다. 마우스 위치 또는 두 손가락 사이의 날짜를 기준으로 확대하며 같은 봉 자동 전환 규칙을 적용합니다. 일반 휠과 모바일 선택 도구의 한 손가락 세로 스크롤은 그대로 사용할 수 있습니다. 두 손가락 입력이 시작되면 진행 중인 그리기를 취소하고, 한 손가락이 남아도 그림을 생성하지 않습니다.

주기를 자동 변경할 때 확대 기준 날짜를 전달하고 `/api/history`에서 해당 날짜를 직접 조회합니다. 버튼은 화면 중심을 기준으로 합니다. 앞쪽 지표 계산용 봉도 함께 확보하며 최대 4페이지까지 조회합니다. 시세가 없거나 요청이 실패하면 최신 날짜로 대체하지 않고 오류·재시도·최근 구간 보기 기능을 제공합니다. 주기가 다른 응답은 차트에 혼합하지 않으며 그림은 기존 계정·종목·주기별 저장 체계를 유지합니다. 그림 저장 중에는 확대·축소로 주기를 바꿀 수 없습니다. 관련 검증: `server/chart-viewport.test.ts`, `tests/chart-zoom.spec.ts`, `tests/chart-gestures.spec.ts`.

### 거래 화면과 탐색 복원

#### 종목 분석·재무제표

PC의 `종목 분석`, 모바일의 `분석` 탭에서 선택 종목의 투자지표, 매출·영업이익·순이익 추이, 손익계산서·재무상태표·재무비율을 조회합니다. `/api/financials/:symbol?period=annual|quarter`는 로그인 사용자만 사용하며 ETF는 별도 상품 정보로 안내합니다. 화면 진입 시에만 조회하고 종목 변경·기간 전환 시 이전 응답이 새 화면에 섞이지 않도록 합니다.

KIS `finance/income-statement`, `balance-sheet`, `financial-ratio`와 `quotations/inquire-price`를 사용합니다. 재무자료는 6시간, 시세 기반 투자지표는 1분 캐시하며 동시 요청을 합칩니다. 일부 조회에 실패해도 다른 자료는 유지하고, 이전 캐시를 표시할 때는 갱신 실패와 수신 시각을 명시합니다. 누락·형식 오류는 0으로 채우지 않습니다.

금액은 억 원, EPS/BPS는 원, 비율은 %입니다. 공식 KIS 2023.12 손익 예시의 매출 `2589355`는 [삼성전자 발표](https://news.samsung.com/global/samsung-electronics-announces-fourth-quarter-and-fy-2023-results)의 258.94조 원과 대조했습니다. [KIS 공식 명세](https://apiportal.koreainvestment.com/apiservice-apiservice?/uapi/domestic-stock/v1/finance/income-statement)상 분기 손익은 연초부터 누적입니다. 연간 응답에도 최근 중간결산이 포함되므로 `stac_month`와 다른 결산 월은 연간 표에서 제외하고 분기 누적으로 안내합니다. 결산 월을 확인하지 못하면 이를 명시하고 연간 실적이라고 단정하지 않습니다. 전년 증감은 같은 결산 월끼리만 계산하며 적자·흑자 전환을 별도로 표시합니다.

연결/별도 구분은 API에 포함되지 않아 임의로 지정하지 않습니다. 서로 다른 결산의 비율·금액을 합치지 않으며 조회 시점 PER/PBR과 선택 결산 EPS/BPS는 구분합니다. 현금흐름표·공시는 아래 DART 연결 기능에서 제공하며 주석은 공시 원문으로 안내합니다. 데모 모드는 실제 기업 수치를 사용하지 않고 가상 자료임을 표시합니다. 검증: `server/financials.test.ts`, `tests/financials.spec.ts`.

#### 종목 분석 확장: 분기·TTM, 기업 비교, 수급, 공시·배당, 추정 실적

`종목 분석` 안의 6개 메뉴에서 필요한 데이터만 조회합니다. `재무 요약`에는 연간·분기 누적·단일 분기·최근 12개월(TTM) 보기를 제공합니다. 단일 분기는 12월 결산 종목의 누적 손익 차이로, TTM은 연속 4분기 손익의 합으로 계산합니다. 이는 **KIS 누적값 기반 추정치**이며 연결/별도·정정 이력 일치는 확인할 수 없습니다. 필요한 분기나 항목이 없으면 표시하지 않습니다. 재무상태표 잔액을 합산하지 않으며 ROE·EPS는 단일 분기·TTM 보기에서 숨깁니다. 단일 분기는 전년 동기와 전분기 비교를 함께 제공합니다.

인증이 필요한 `/api/research/:symbol/:section`의 `section`은 다음과 같습니다. ETF와 없는 종목, 허용하지 않은 기간·회계 기준·비교 개수는 거절합니다.

- `peers?symbols=000660,035420`: 기준 종목 포함 최대 3개를 직접 골라 공통 연간 결산으로 매출·이익·ROE·성장률을 비교합니다. PER/PBR·시가총액은 조회 시점 값입니다. `search-stock-info`의 표준산업분류와 분류 차이를 표시하며 테마를 업종으로 간주하지 않습니다. 공통 결산이 없으면 실적을 임의로 다른 기간에서 가져오지 않습니다.
- `flows`: [KIS 주식현재가 투자자](https://apiportal.koreainvestment.com/apiservice-apiservice?/uapi/domestic-stock/v1/quotations/inquire-investor)의 KRX 일별 외국인·기관·개인 순매수 **수량(주)**과 종가를 표시합니다. 최신 미집계 날짜는 별도로 알리고 최근 집계된 1/5/20거래일을 합산합니다. 기간 중간의 누락을 건너뛰거나 0으로 채워 합계로 표시하지 않습니다. 5분 캐시입니다.
- `dividends`: [KIS 예탁원 배당 일정](https://apiportal.koreainvestment.com/apiservice-apiservice?/uapi/domestic-stock/v1/ksdinfo/dividend)으로 과거 365일~향후 90일의 기준일·현금배당액·지급일을 조회합니다. 미제공 지급일을 추정하거나 배당 기준일을 배당락일로 표시하지 않습니다. 모의 계좌 자동 지급 기능과 독립된 정보 조회입니다. 6시간 캐시입니다.
- `estimates`: [KIS 종목 추정 실적](https://apiportal.koreainvestment.com/apiservice-apiservice?/uapi/domestic-stock/v1/quotations/estimate-perform)의 `output2` 매출·영업이익·순이익을 `output4` 결산과 매핑합니다. `E` 표시와 자료 기준일을 유지합니다. 손익 금액 단위는 억 원으로 기존 실제 실적과 대조했으며, 공식 명세의 모호한 투자지표 스케일은 임의 적용하지 않습니다. 발표 전 예상치 이력이 없으므로 어닝 서프라이즈·예상치 수정률을 계산하지 않으며 시장 전체 컨센서스라고 표시하지 않습니다. 6시간 캐시입니다.
- `filings`: OpenDART의 최근 90일 공시 최대 100건. 실적·배당·자본 변동·자사주·정정공시를 제목으로 분류하고 유효한 접수번호로 원문 링크를 생성합니다. 10분 캐시입니다.
- `dart?year=2025&report=11011&basis=CFS`: OpenDART 전체 재무제표. `CFS` 연결/`OFS` 별도, 11013 1분기/11012 반기/11014 3분기/11011 사업보고서를 명시적으로 선택합니다. 현금흐름 요약 및 CF/BS/IS/CIS 계정을 표시합니다. 분·반기 손익의 3개월 금액과 누적액, 원본 통화·비교 기간을 구분합니다. 원화만 억 원으로 환산하고 불명확한 계정은 합치지 않습니다. 6시간 캐시입니다.

DART 연결은 **준비 상태**입니다. 운영자가 `.env`에 `DART_API_KEY`를 설정하고 앱 컨테이너를 재생성하면 활성화됩니다(`OPENDART_API_KEY`도 호환). 키가 없으면 네트워크 요청 없이 `unconfigured`를 반환하고 화면은 연결 대기를 표시합니다. 키를 브라우저·로그·응답에 전달하지 않습니다. 공식 고유번호 ZIP의 종목코드→기업코드 매핑을 24시간 캐시하며, 연결 재무제표가 없다고 별도로 자동 대체하지 않습니다. 등록 오류·한도 초과·형식 오류는 자료 없음과 구분합니다. 실패한 조회는 1분 후 재시도하고 이전 캐시가 있으면 수신 시점과 갱신 지연 상태를 유지합니다.

DART 기준: [전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020), [공시 검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001), [기업 고유번호](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018). 검증은 `server/research.test.ts`, `tests/research.spec.ts`에서 계산·누락·오류·키 미설정·모의 DART 연결·모바일 화면을 확인합니다. 실제 DART 응답 검증은 운영 키 설정 이후에 필요합니다.

호가와 주문은 뉴스보다 앞에 나란히 배치합니다. 1,251px 이상에서는 차트 옆에, 601~1,250px에서는 종목·차트 영역 바로 아래에 표시합니다. 모바일은 호가·주문 탭을 사용하며 호가를 누르면 지정가 주문 가격에 반영됩니다. 수량·매수/매도 방향은 유지하고 선택한 가격을 호가창에서 강조합니다. 검증: `tests/book-layout.spec.ts`.

트레이딩에는 자산·손익·주문 가능 금액을 축약해 표시합니다. 전체 금액은 요약의 툴팁과 내 계좌, 주문 화면에서 확인합니다. 차트 자세히 보기는 가격·거래량·20기간 이동평균만 표시하는 ‘기본 차트’로 시작합니다. ‘분석 차트’로 바꾸면 기존 보조지표·이동평균 선택을 다시 표시하며, 보기 방식은 계정별 브라우저에 저장합니다. 하단 ‘보조지표·그리기·차트 설정’에서 필요한 도구를 하나씩 열고, 모바일은 하단 패널로 표시합니다. 지표를 바꾸면 분석 차트로 전환하고, 그리기 도구를 고르면 패널을 닫아 차트에 바로 그릴 수 있습니다. 상세 지표 수치는 보조지표 패널, 과거 구간·봉 자동 전환·시고저종·저장 상태는 차트 설정에서 확인합니다. Escape는 열린 도구 패널을 먼저 닫습니다. 검증: `tests/chart-simple.spec.ts`. 모바일 주문 금액·버튼은 하단 메뉴 위에 표시하며 주문 영역을 지나 기록으로 내려가면 숨깁니다. 매매 이유와 투자 계획은 선택 입력으로 접어 두며 탭을 바꿔도 작성 내용은 유지합니다.

계좌는 보유 종목·미체결·체결 내역·성과·일지 탭으로 구분합니다. 체결 내역에는 체결·취소·만료 등 종료된 주문을 표시하고 미체결 탭에서 정정·취소합니다. 모바일 시장 순위는 핵심 수치만 먼저 표시하고 거래량·포착 시각 등은 상세로 펼칩니다. 종목의 시장·상품·테마 조건은 필터를 펼쳐 설정하며 적용 조건은 접힌 상태에서도 보입니다.

화면·종목·봉·탭·검색 조건은 URL에 반영합니다. 예: `/?page=trade&symbol=000660&period=W&tab=order`, `/?page=account&account=pending`. 뒤로가기·앞으로가기·새로고침에서 조건과 스크롤을 복원하며 매매 이유·비밀번호·주문 내용은 URL에 저장하지 않습니다. 기존 `#education/week/1` 형식은 관리자 권한 확인과 함께 유지합니다. 검증: `server/workspace-navigation.test.ts`, `tests/workspace-ui.spec.ts`.
